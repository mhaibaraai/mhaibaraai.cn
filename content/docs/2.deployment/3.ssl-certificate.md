## 方案选择

| 方案 | 适用场景 | 优点 | 缺点 |
|---|---|---|---|
| Cloudflare Origin 证书 | 流量全程经 Cloudflare 代理 | 有效期 15 年、免续签 | 仅 Cloudflare 信任，直连源站会报不信任 |
| Let's Encrypt + acme.sh | 直连源站或需要公共 CA 证书 | 公共浏览器信任、免费 | 需配置 DNS API 自动续签 |

## Cloudflare Origin 证书

1. 在 Cloudflare Dashboard 对应域名下进入 **SSL/TLS → Origin Server** 生成证书（覆盖 `example.com` 与 `*.example.com`），保存为 `~/nginx/ssl/example.com.pem` 与 `example.com.key`。
2. 在 **SSL/TLS → Overview** 中必须选择 **Full** 或 **Full (strict)**，切勿设为 Flexible。

## Let's Encrypt + acme.sh 自动续签

在 Cloudflare 创建一个包含 `Zone - DNS - Edit` 和 `Zone - Zone - Read` 权限的 API Token，写入 `~/.acme.sh/account.conf` 后签发并安装证书：

```sh [sh]
cat >> ~/.acme.sh/account.conf << 'EOF'
CF_Token="your_api_token"
CF_Zone_ID="your_zone_id"
EOF

# 显式指定 letsencrypt，避开 ZeroSSL 速率限制
~/.acme.sh/acme.sh --issue --dns dns_cf \
  -d example.com \
  -d "*.example.com" \
  --server letsencrypt

# 安装证书并配置续签后自动重载 Nginx
~/.acme.sh/acme.sh --install-cert -d example.com \
  --key-file ~/nginx/ssl/example.com.key \
  --fullchain-file ~/nginx/ssl/example.com.pem \
  --reloadcmd "docker exec nginx nginx -s reload"
```

验证定时续签任务：`crontab -l | grep acme`，可手动执行 `~/.acme.sh/acme.sh --cron --home ~/.acme.sh` 测试。

## Nginx HTTPS 最小配置

```nginx [conf/conf.d/ssl.conf]
server {
    listen 80;
    server_name example.com;
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name example.com;

    ssl_certificate /etc/nginx/ssl/example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/example.com.key;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    location / {
        # 反代或静态资源配置
    }
}
```

## 常见故障排查

### HTTP 525 SSL Handshake Failed

Cloudflare 无法与源站完成 TLS 握手，按以下顺序定位：

```sh [sh]
sudo ss -tlnp | grep 443                                           # 确认 443 端口已监听
curl -vk https://127.0.0.1 -H "Host: example.com" 2>&1 | head -20  # 本地验证 TLS 握手
openssl x509 -in ~/nginx/ssl/example.com.pem -noout -issuer -dates # 检查证书内容与有效期
docker exec nginx nginx -t                                         # 校验 Nginx 配置
```

同时确认安全组放行 `443/tcp`，且 Cloudflare SSL 模式为 **Full** 或 **Full (strict)**。

### ERR_TOO_MANY_REDIRECTS

Cloudflare 模式设为 **Flexible** 时，Cloudflare 以 HTTP 回源，源站 Nginx 又 `301` 重定向到 HTTPS，形成死循环。将模式改为 **Full** 或 **Full (strict)** 即可。

### 提示「证书链不完整」

Cloudflare Origin 证书并非公共 CA 签发，上传到云厂商控制台时会提示证书链不完整。这是正常现象，Origin 证书只放在自己的源站 Nginx 中使用，无需上传第三方平台。

### acme.sh 报 `retryafter=86400`

ZeroSSL 默认配额触发限流，追加 `--server letsencrypt --force` 切换到 Let's Encrypt 重试即可。

### acme.sh 报 `invalid domain`

通常是 API Token 权限不足或 `CF_Zone_ID` 填错。核对 Token 包含 `Zone - DNS - Edit` 与 `Zone - Zone - Read` 后，覆盖 `~/.acme.sh/account.conf` 中的旧凭证：

```sh [sh]
sed -i '/CF_Token/d;/CF_Zone_ID/d' ~/.acme.sh/account.conf
cat >> ~/.acme.sh/account.conf << 'EOF'
CF_Token="new_token"
CF_Zone_ID="new_zone_id"
EOF
```
