## Compose 基础结构

使用自定义桥接网络 `webnet` 让同栈容器互通，同时通过 `extra_hosts` 允许容器访问宿主机服务：

```yaml [~/nginx/docker-compose.yml]
services:
  nginx:
    image: nginx:latest
    container_name: nginx
    restart: always
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./conf/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./conf/conf.d:/etc/nginx/conf.d:ro
      - ./ssl:/etc/nginx/ssl:ro
      - ./logs:/var/log/nginx
    extra_hosts:
      - "host.docker.internal:host-gateway"
    networks:
      - webnet

networks:
  webnet:
    name: webnet
    driver: bridge
```

## 两种反向代理写法

### 反代同网络应用容器

容器重建后内网 IP 会变化，直接写 `proxy_pass http://app:3000;` 会导致 Nginx 启动时解析失败或缓存旧 IP。使用 Docker 内置 DNS `127.0.0.11` 配合变量形式的上游地址，让 Nginx 在请求时动态解析：

```nginx [conf/conf.d/app.conf]
location / {
    resolver 127.0.0.11 valid=30s;
    set $upstream app:3000;
    proxy_pass http://$upstream;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

### 反代宿主机进程

若应用通过 PM2 等方式直接跑在宿主机端口，Compose 需配置上面的 `extra_hosts`，随后直接指向 `host.docker.internal`：

```nginx [conf/conf.d/app.conf]
location / {
    proxy_pass http://host.docker.internal:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

## 常用校验与重载

修改配置后先检查语法再平滑重载，避免直接重启导致报错下线：

```sh [sh]
docker compose exec nginx nginx -t
docker compose exec nginx nginx -s reload
```

## 网络排查：IPv4 不通但 IPv6 正常

Docker 对 IPv4 依赖 iptables DNAT 做端口映射，容易与云厂商安全组或宿主机防火墙规则冲突：

```sh [sh]
# 检查端口映射与 NAT 规则
docker port nginx
sudo iptables -t nat -L -n | grep 443
```

处理顺序：优先核对云厂商安全组与 `ufw` 是否放行 `80`/`443`；若环境支持 IPv6，建议同时配置 `AAAA` 解析；尽量避免使用 `network_mode: host` 绕过隔离。

HTTPS 证书选型与 Nginx SSL 配置见 [SSL 证书配置](/docs/deployment/ssl-certificate)。
