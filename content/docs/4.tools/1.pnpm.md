## 信任降级错误（ERR_PNPM_TRUST_DOWNGRADE）

pnpm 10.21+ 引入 `trustPolicy` 防范供应链劫持。npm 包的信任等级依次为 **可信发布者（Trusted Publisher）** > **来源证明（Provenance Attestation）** > **无证明（No Evidence）**。当新版本信任级别低于早期版本时，安装会直接中止：

```text
ERR_PNPM_TRUST_DOWNGRADE  High-risk trust downgrade for "package-name@x.x.x" (possible package takeover)

Earlier versions had provenance attestation, but this version has no trust evidence.
```

确认是已知可信包未及时配置 provenance（如 `undici`、[相关 Issue](https://github.com/nodejs/undici/issues/4666) 或 `chokidar`）后，可在 `pnpm-workspace.yaml` 中为特定包添加豁免（参见 [pnpm#10329](https://github.com/pnpm/pnpm/issues/10329)）：

```yaml [pnpm-workspace.yaml]
trustPolicy: no-downgrade
trustPolicyExclude:
  - undici
  - undici-types
  - chokidar
```

## 自举失败（integrity in undefined）

pnpm 10+ 默认开启 `managePackageManagerVersions`。当本机 pnpm 版本与 `package.json` 的 `packageManager` 字段不一致时，pnpm 会先自举安装目标版本到全局目录，而在 pnpm 11.12.0 上该路径存在缺陷并直接崩溃：

```text
[ERROR] Cannot use 'in' operator to search for 'integrity' in undefined

pnpm: Cannot use 'in' operator to search for 'integrity' in undefined
    at createFullPkgId (.../pnpm/dist/pnpm.mjs)
    at lockfileToDepGraph (.../pnpm/dist/pnpm.mjs)
    at headlessInstall (.../pnpm/dist/pnpm.mjs)
    at async installPnpmToGlobalDir (.../pnpm/dist/pnpm.mjs)
```

::warning
**关键判据**：调用栈出现 `installPnpmToGlobalDir`，且连执行 `pnpm -v` 都报同一错误。说明问题出在 pnpm 自举阶段，与项目 `node_modules` 或 `pnpm-lock.yaml` 无关，无需删重装依赖。
::

**原因**：自举时 `buildLockfileFromEnvLockfile` 处理带 peer 依赖的快照（如 `fdir@6.5.0(picomatch@4.0.5)`）未取到 `packages[depPath]` 且未回退基础包，导致对象缺少 `resolution` 块并抛出 `TypeError`。该问题已在 [pnpm#12959](https://github.com/pnpm/pnpm/issues/12959) / [PR #13082](https://github.com/pnpm/pnpm/pull/13082) 修复。

若在本地或 CI（例如 `pnpm/action-setup@v6` 强制先装固定 bootstrap 版本再跑 `self-update`）命中受影响版本，可按如下方式绕过自举路径：

::code-group

```sh [本地：对齐本机 pnpm 版本]
brew upgrade pnpm
pnpm -v   # 确认与 packageManager 一致，跳过自举
```

```yaml [CI：改用 action-setup@v5]
# v5 直接通过 npm 安装目标版本，不走 self-update
- uses: pnpm/action-setup@v5
```

::
